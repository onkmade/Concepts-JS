### Reading and Changing Text and HTML Content in the DOM

In DOM manipulation, one of the most common tasks is reading or modifying the content inside HTML elements. JavaScript provides several properties and methods for this purpose, but the two primary ones are `textContent` and `innerHTML`. Understanding the difference between them is crucial because they serve slightly different purposes and have important security and performance implications. Both properties are available on every element node, and they allow you to get (read) or set (change) the content of an element dynamically, making your page interactive without reloading.

`textContent` is the safest and most straightforward way to work with plain text. It represents all the text contained within an element and its descendants, including hidden text and script/style elements, but it completely ignores any HTML markup. When you read `textContent`, you get a plain string of all the text nodes. When you set `textContent`, any existing content (including child elements) is replaced with the new plain text string — no HTML parsing occurs. This makes `textContent` ideal for most cases where you just want to display or update simple text, such as paragraph content, labels, or user messages. It's also more secure because it cannot introduce malicious HTML or scripts.

In contrast, `innerHTML` treats the content as HTML markup. When you read `innerHTML`, you get a string containing the HTML of the element and its descendants (including tags). When you set `innerHTML`, the browser parses the string as HTML and creates new DOM nodes accordingly. This allows you to insert formatted text, links, images, or entire structures — very powerful for building dynamic content like lists or tables. However, this power comes with a major risk: if the string contains untrusted content (e.g., user input), it can execute malicious scripts (XSS attacks). For this reason, `innerHTML` should be used cautiously and only with sanitized data.

There's also `innerText` (less commonly used), which is similar to `textContent` but respects CSS styling (e.g., ignores hidden text with `display: none`) and includes rendered line breaks. However, it's slower and non-standard in some ways, so `textContent` is generally preferred for plain text operations.

### Practical Comparison

```html
<div id="container">
  <p>Hello <strong>bold</strong> world!</p>
  <script>alert("bad")</script>
</div>

<script>
  const container = document.getElementById("container");

  // Reading with textContent
  console.log(container.textContent);
  // Output: "Hello bold world!\n                alert(\"bad\")"

  // Reading with innerHTML
  console.log(container.innerHTML);
  // Output: "\n  <p>Hello <strong>bold</strong> world!</p>\n  <script>alert(\"bad\")</script>\n"

  // Changing with textContent (safe)
  container.textContent = "New plain text";
  // Result: all child elements removed, only plain text remains

  // Changing with innerHTML (powerful but risky)
  container.innerHTML = "<em>New</em> <strong>formatted</strong> content";
  // Result: creates new <em> and <strong> elements
</script>
```

### Best Practices Summary

- Use **`textContent`** for:
  - Displaying/updating simple text (titles, messages, form labels)
  - Security-critical situations (user input)
  - Performance (faster than innerHTML)

- Use **`innerHTML`** only when:
  - You need to insert actual HTML markup (lists, tables, formatted text)
  - The content is trusted or properly sanitized

- Avoid `innerHTML` with untrusted data — prefer creating elements with `document.createElement()` and `appendChild()` for maximum security.

Mastering `textContent` and `innerHTML` gives you full control over what the user sees on the page — the core of dynamic web applications.
