### Event Delegation in Depth

Event delegation is a powerful and efficient technique in JavaScript DOM manipulation that allows you to handle events on multiple child elements by attaching **only one event listener** to a common parent (ancestor) element. Instead of adding a separate listener to each child (which can be slow and memory-intensive when children are added dynamically), you let the event "bubble" up from the child to the parent, then use the event object to determine exactly which child triggered it.

This pattern is essential for performance, clean code, and working with dynamically added elements.

#### How Events Bubble (The Foundation)

In the DOM, most events **bubble** — when an event fires on an element, it first runs handlers on that element, then on its parent, then grandparent, all the way up to the `document` and `window`. This bubbling phase is what makes delegation possible.

```html
<div id="parent">
  <button>1</button>
  <button>2</button>
  <button>3</button>
</div>
```

If you click a button, the click event bubbles:  
button → div#parent → body → html → document → window

#### Traditional (Inefficient) Way — One Listener Per Child

```js
document.querySelectorAll("button").forEach(btn => {
  btn.addEventListener("click", () => {
    console.log("Clicked button " + btn.textContent);
  });
});
```

Problems:
- If buttons are added later, they won't have listeners.
- 100 buttons = 100 listeners = memory/performance cost.

#### Event Delegation — One Listener on Parent

```js
document.getElementById("parent").addEventListener("click", (event) => {
  if (event.target.tagName === "BUTTON") {  // or check class/id
    console.log("Clicked button " + event.target.textContent);
  }
});
```

Advantages:
- Works on **existing and future** buttons (perfect for dynamic content).
- Only **one** listener — better performance.
- Cleaner code.

#### Key Properties in the Event Object for Delegation

- `event.target` — the **actual** element that was clicked (the deepest one).
- `event.currentTarget` — the element the listener is attached to (the parent).
- `event.stopPropagation()` — stops bubbling if needed.

Example distinguishing them:

```js
parent.addEventListener("click", (e) => {
  console.log("Target:", e.target.textContent);        // the button clicked
  console.log("Current:", e.currentTarget.id);         // "parent"
});
```

#### Real-World Example: Dynamic Todo List with Delete Buttons

```js
const list = document.getElementById("taskList");

document.getElementById("addBtn").addEventListener("click", () => {
  const li = document.createElement("li");
  li.innerHTML = `Task <span class="delete">×</span>`;
  list.appendChild(li);
});

// One delegation listener
list.addEventListener("click", (e) => {
  if (e.target.classList.contains("delete")) {
    e.target.parentElement.remove(); // delete the whole task
  }
});
```

Even tasks added after page load are deletable — delegation handles them automatically.

#### Advanced: Using `closest()` for More Robust Matching

```js
list.addEventListener("click", (e) => {
  const deleteBtn = e.target.closest(".delete");
  if (deleteBtn) {
    deleteBtn.parentElement.remove();
  }
});
```

`closest()` walks up from the clicked element to find the nearest matching ancestor — works even if clicking inside the "×" (SVG, text, etc.).

#### When to Use Event Delegation

- Always for **dynamic elements** (added/removed at runtime).
- For large lists (hundreds/thousands of items) — performance win.
- When you want centralized event handling logic.

#### When NOT to Use It

- For very small static lists (3-5 items) — direct listeners are fine.
- If you need to stop propagation early or use capture phase.

#### Summary

Event delegation leverages event bubbling to handle events efficiently with a single listener on a parent. It uses `event.target` (or `closest()`) to identify the originating child. It's the **professional standard** for interactive lists, tables, galleries, and any dynamic content.

Master this, and your code becomes scalable, performant, and maintainable — exactly how real web apps are built.
