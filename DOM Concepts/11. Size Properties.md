**Here are the main size-related properties in JavaScript/DOM that developers actually use in practice (2025 perspective)**

| Property                        | Includes padding | Includes border | Includes margin | Includes scrollbar | Affected by CSS transform | Forces layout/reflow | Most common real use case                              | How often used (rough estimate) |
|---------------------------------|------------------|-----------------|-----------------|---------------------|---------------------------|-----------------------|----------------------------------------------------------|---------------------------------|
| `offsetWidth` / `offsetHeight`  | Yes              | Yes             | **No**          | Yes                 | **No**                    | Yes                   | Real visible box size, centering, dropdown positioning   | ★★★★★ very frequent            |
| `clientWidth` / `clientHeight`  | Yes              | **No**          | **No**          | **No**              | **No**                    | Yes                   | Inner content area + padding (without borders/scrollbar) | ★★★★ frequent                  |
| `scrollWidth` / `scrollHeight`  | Yes              | Yes             | **No**          | **No**              | **No**                    | Yes                   | Full content size (even parts hidden by scroll)          | ★★★ quite common               |
| `getBoundingClientRect().width` | Yes              | Yes             | **No**          | Yes                 | **Yes**                   | Yes                   | Precise on-screen size after scale/rotate/translate      | ★★★★ very common               |
| `getBoundingClientRect().height`| same as above                                                                                                              |                                                          |                                 |
| `element.style.width`           | —                | —               | —               | —                   | —                         | **No** (just reading) | The CSS width value you set (may be %, auto, etc.)       | ★★ mostly for writing          |
| `window.getComputedStyle(el).width` | —            | —               | —               | —                   | **No**                    | Yes                   | Resolved CSS width (usually in px)                       | ★★–★★★ when you really need it  |

### Quick mental map – which one to choose?

```text
I want to know the size of the element box as user sees it
├── Including border, padding, scrollbar, NOT affected by transform?        → offsetWidth / offsetHeight
├── After CSS transform (scale, rotate, translate)?                         → getBoundingClientRect().width/height
├── Only content area + padding (no border, no scrollbar)?                  → clientWidth / clientHeight
├── Full scrollable content size (even if currently scrolled/hidden)?       → scrollWidth / scrollHeight
└── I want to know what CSS value is currently applied (may be %, auto…)?   → getComputedStyle().width
```

### Practical comparison examples (very common patterns)

```javascript
const box = document.querySelector('.box');

// Assume:
// width: 300px;
// padding: 20px;
// border: 10px solid;
// scrollbar: ~15px wide
// transform: scale(0.6);

console.log(box.offsetWidth);              // ≈ 300 + 40 + 20 + 15 = 375px
console.log(box.clientWidth);              // ≈ 300 + 40         = 340px
console.log(box.scrollWidth);              // ≥ clientWidth (bigger if content overflows)
console.log(box.getBoundingClientRect().width); // ≈ 375 * 0.6 ≈ 225px  ← after scale!

console.log(box.offsetWidth === box.clientWidth + box.clientLeft*2); // usually true (clientLeft = border left)
```

### Very frequent real-world usage patterns (2024–2025)

```javascript
// 1. Centering (most classic use of offsetWidth)
popup.style.left = (window.innerWidth - popup.offsetWidth) / 2 + 'px';

// 2. Detecting text overflow / ellipsis needed
if (item.scrollWidth > item.offsetWidth) {
    item.title = item.textContent; // tooltip with full text
}

// 3. Perfect dropdown / popover positioning
const spaceRight = window.innerWidth - (trigger.getBoundingClientRect().right);
if (spaceRight < dropdown.offsetWidth) {
    dropdown.style.right = '0';
    dropdown.style.left = 'auto';
}

// 4. Equal width cards in grid (very popular pattern)
const cards = [...document.querySelectorAll('.card')];
const widest = Math.max(...cards.map(c => c.offsetWidth));
cards.forEach(c => c.style.minWidth = widest + 'px');

// 5. Knowing real visible size after transform (tooltip, drag & drop, animations)
const draggedElementRealSize = dragged.getBoundingClientRect();
```

### Quick cheat-sheet people actually keep in notes/snippets

```text
offsetWidth    → "what's the real box size I see" (border-box + scrollbar)
clientWidth    → "content area + padding only"
scrollWidth    → "how wide is all the content if I scroll"
getBoundingRect → "what size does it really appear on screen after transforms"
```

Pick the one that matches **what you actually need to measure** — most of the time it's either `offsetWidth` or `getBoundingClientRect().width`.
