### Modern Practical Hierarchy (what people really use in 2025)

Level 1 – Most common pattern (≈70–80% of cases)
```js
if (condition) {
  // do something
} else {
  // do something else
}
```

Level 2 – Multiple clear conditions (≈15–25%)
```js
if (score >= 90) {
  grade = "A"
} else if (score >= 80) {
  grade = "B"
} else if (score >= 70) {
  grade = "C"
} else {
  grade = "F"
}
```

Level 3 – Many exact values → switch (much cleaner than 10+ else-if)
```js
switch (statusCode) {
  case 200:
  case 201:
    message = "Success"
    break
  case 400:
    message = "Bad Request"
    break
  case 401:
    message = "Unauthorized"
    break
  case 404:
    message = "Not Found"
    break
  case 500:
    message = "Server Error"
    break
  default:
    message = "Unknown error"
}
```

Level 4 – Very modern alternatives people love (functional style)

```js
// 1. Ternary (one-liner simple decisions)
const message = age >= 18 ? "Adult" : "Minor"

// 2. Object / Map lookup (clean replacement for big switch)
const gradeMap = {
  90: "A",
  80: "B",
  70: "C",
  60: "D"
}

const getGrade = score => gradeMap[Object.keys(gradeMap).find(k => score >= k)] || "F"

// 3. Early return pattern (very popular in functions)
function canEnterClub(age, hasID) {
  if (age < 18)          return "Too young"
  if (!hasID)            return "No ID"
  if (isBanned(user))    return "Banned"
  return "Welcome!"
}
```

### Quick Decision Map – Which one to choose?

```text
How many conditions?     → Choose this
─────────────────────────┼───────────────────────────────
1 condition              → if / ternary
Exactly 2 outcomes       → if-else / ternary
3–6 clear ranges         → if – else if – else
Many exact values        → switch / object lookup
Very complex logic       → early returns + guard clauses
Need to assign value     → ternary / object map
Want clean & readable    → early returns / object lookup
```

Start with simple `if → else if → else` and `ternary`, then gradually learn the others when you feel they're cleaner.
