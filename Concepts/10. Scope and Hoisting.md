### Scope and Hoisting in JavaScript (Basic Level)

Scope and hoisting are two closely related concepts that control **where variables are accessible** and **when they are created** in your code. Understanding them at a basic level will help you avoid common bugs like "undefined" values or unexpected behavior.

#### 1. Scope — Where Variables Are Accessible

Scope determines the visibility and lifetime of variables.

There are two main types at the basic level:

- **Global Scope**: Variables declared outside any function (or with `var` in older code) are global and accessible everywhere.

- **Function Scope (Local Scope)**: Variables declared inside a function with `let` or `const` are only accessible inside that function.

```js
let globalVar = "I am global";   // Global scope

function testScope() {
  let localVar = "I am local";   // Local scope
  console.log(globalVar);        // Works: "I am global"
  console.log(localVar);         // Works: "I am local"
}

testScope();

console.log(globalVar);   // Works
console.log(localVar);    // Error: localVar is not defined
```

**Key Rule**: Variables inside functions are **private** to that function.

#### 2. Block Scope (with `let` and `const`)

`let` and `const` have **block scope** — they are only accessible inside the nearest curly braces `{}` (like in `if`, `for`, etc.).

```js
if (true) {
  let blockVar = "I am block-scoped";
  const another = "Me too";
  console.log(blockVar); // Works
}

console.log(blockVar);   // Error: blockVar is not defined
```

`var` does **not** have block scope (avoid it for this reason).

#### 3. Hoisting — Variables and Functions Are "Moved" to the Top

Hoisting is JavaScript's behavior of moving declarations to the top of their scope **before code execution**.

- **Function declarations** are fully hoisted — you can call them before defining them.

- **`var` declarations** are hoisted but initialized as `undefined`.

- **`let` and `const`** are hoisted but **not initialized** — accessing them before declaration gives a ReferenceError (Temporal Dead Zone).

```js
console.log(varVar);     // undefined (hoisted)
var varVar = "I am hoisted";

console.log(letVar);     // ReferenceError!
let letVar = "Not hoisted value";

greet();                 // Works! Fully hoisted
function greet() {
  console.log("Hello!");
}
```

### Practical Example

```js
function calculateAge(birthYear) {
  const currentYear = 2025;
  let age = currentYear - birthYear;  // Local variable

  if (age >= 18) {
    let message = "Adult";            // Block scope
    console.log(message);
  }

  console.log(age);         // Works
  // console.log(message);  // Error — block scope
  return age;
}

console.log(calculateAge(2000)); // 25
```

### Summary (Basic Rules to Remember)

- Use `const` and `let` — they have proper block/function scope.
- Variables inside functions are private.
- Don't access `let`/`const` before declaration.
- Function declarations can be called anywhere in their scope.
- Avoid `var` — it has weird hoisting and no block scope.

This basic understanding prevents 90% of scope-related bugs.

### Practice

Create a function `isPositive(number)` that:
- Returns "Positive" if number > 0
- "Zero" if 0
- "Negative" otherwise
- Use `let` for a local message variable

**Solution:**
```js
function isPositive(number) {
  let result;
  if (number > 0) {
    result = "Positive";
  } else if (number === 0) {
    result = "Zero";
  } else {
    result = "Negative";
  }
  return result;
}

console.log(isPositive(5));   // "Positive"
console.log(isPositive(-3));  // "Negative"
```
